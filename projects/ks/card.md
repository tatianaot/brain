Порядок тем: создание проекта → моделирование → таблицы → графики → интерфейсы → импорт → виджеты → приложения.

**Хранение документов — Яндекс.Диск, не Teachbase.** Папка документов в Teachbase не подходит: нет автоматического назначения доступа по курсу. Все файлы (презентации, Excel, глоссарий, график обучения, подсказки по инструментам) лежат на Диске, ссылки в LMS ведут туда.

**Сроки обучения зафиксированы договором:** каждый курс — две недели, затем следующий. Доработка укладывается в те же две недели, дополнительного времени не даётся; график идёт приложением к договору. Промежуточные проверки обязательны: обучающийся не переходит к следующему модулю без подтверждения куратора, срок проверки — максимум три рабочих дня.

**Продуктовая матрица — три линейки** (13.10):

1. Курсы на учебном проекте: базовый, продвинутый, экспертный — без изменений.
2. Интеграции: обновление курса по СУБД плюс новый курс «Интеграции Про» по внешним системам и сервисам.
3. Инженерно-архитектурный уровень: один объединённый курс с лонгридами и интерактивом, кейсы заказчиков, абонемент на сессии (12–13 недель).

**Кейс-сессии выделены в отдельный продукт** в трёх форматах: архитектурные задачи (2–3 часа, несколько встреч), экспресс-разбор кейса заказчика (одна встреча), абонемент. Логика продажи: заказчик берёт базовый и продвинутый курс, а вместо полной линейки — разбор своего кейса. Формат уже проверен на практике с Норникелем в рамках ОПЭ.

**Обратная связь ГИПов (09.10) — важная и неприятная.** Экспертный курс хвалят. Интеграционный слишком базовый, к замене интегратора не готовит. Архитектурный — много текста без приоритизации, низкая эффективность. Курс ГИП — «скорее курс РП», софт-скиллы берутся на бесплатных курсах по Agile. Базовый сам по себе недостаточен. Учебные кейсы привязаны к одной отрасли, и это пугает новичков при смене контекста — нужна вариативность. По формату: короткие видео на 5 минут и записи вебинаров удобнее часовых синхронных сессий, действующим ГИПам некогда учиться синхронно.

## Правила проекта
- **Почта проекта — `tatyana.otbetkina@im.systems`**, пересылается в сборник `otbetkina.vault@gmail.com` под ярлыком **KS**. В прогонах искать `label:KS` — по названию, не по идентификатору.
- Почти все слова этого проекта — имена собственные (KS, IM Systems, Knowledge Space, ГПН, Teachbase). По правилу «имя собственное перевешивает общее слово» они решают спор с любым общим словом области.
- **«ису» ищем как отдельное слово, а не как кусок другого**: «ису» встречается внутри «рисунок», «спису», «Исузу». Совпадение внутри слова — не сигнал.
- **«ЛМС» — неоднозначное слово**: своя ЛМС есть и здесь, и у МАИ. При нём уточнять, проект по одному этому слову не определять.
- «Knowledge Space» и «KS» — почти наверняка одно и то же. Если подтвердится, «ks» останется коротким алиасом.
